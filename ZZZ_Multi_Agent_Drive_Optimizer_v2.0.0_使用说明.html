ZZZ Multi-Agent Drive Optimizer v2.0.0 使用说明

本说明适用于 ZZZ_Multi_Agent_Drive_Optimizer_v2.0.0.exe。

它是一款《绝区零》驱动盘库存管理和基础面板配装工具，主要用途是：导入或录入已有驱动盘，按角色、套装、主属性和面板目标搜索 4+2 配装，并在多个角色之间分配互不冲突的驱动盘。

本工具不是完整战斗伤害模拟器。角色等级、核心技、音擎基础属性、驱动盘主副属性及可静态计算的 2 件套效果会计入面板；依赖进场、叠层、敌人状态、队伍条件或技能触发的效果通常只作为实战参考展示。

1. 启动与退出

  1. 双击 ZZZ_Multi_Agent_Drive_Optimizer_v2.0.0.exe。
  2. 正式版不会弹出 Terminal，浏览器会自动打开本地 WebUI。
  3. 使用页面右上角的“退出程序”停止本地服务，然后关闭浏览器页面。
  4. 如果只关闭浏览器标签页而没有点击“退出程序”，本地服务仍可能在后台运行；可以重新启动程序打开页面，或在任务管理器中结束程序。

程序只在本机提供页面和计算服务，不需要把驱动盘库存上传到远程服务器。

2. 页面结构

页面分为三个主要区域：

  1. 录入驱动盘：手工录入、截图 OCR，以及启动随包 Scanner。
  2. 驱动盘库存：查看、筛选、编辑和删除已经导入的驱动盘。
  3. 角色配装与结果：选择角色、音擎、4+2 套装、主属性限制、目标和优先级，并在当前角色折叠卡片中查看前 20 套单角色候选；多角色实际分配显示在各角色卡片内。

页面顶部提供：

  • 导出通用驱动盘 JSON：导出可与其他兼容工具交换的驱动盘数据。
  • 导出完整备份：备份本软件的库存、角色配装方案和本地驱动盘归属。
  • 导入 JSON（自动识别）：自动识别 Scanner 文件、通用驱动盘 JSON 或本软件完整备份。
  • 退出程序：关闭本地服务。

3. 使用 ZZZ Scanner Next 批量扫描

本配装器可以使用 ZZZ Scanner Next 生成的驱动盘数据。

ZZZ Scanner Next 是独立的 Windows 驱动盘可见界面扫描器。根据其官方说明，它通过切换到游戏窗口、点击驱动盘、滚动列表、截图并在本机运行 PP-OCRv5 来识别数据；它不读取游戏内存、不注入代码，也不安装游戏插件。

3.1 支持环境

上游当前说明的主要要求是：

  • Windows 10 1809（Build 17763）或更高版本，或 Windows 11；
  • x64 Windows；
  • 本地 PC 客户端或云·绝区零；
  • 游戏使用简体中文界面；
  • 主要适配 16:9 驱动盘仓库界面；
  • OCR 在本机运行。

非中文界面、非 16:9 布局、自定义 UI 缩放、强 HDR/滤镜、遮挡窗口以及未来游戏 UI 改版都可能影响识别。

3.2 下载 Scanner

从官方项目下载：

  • 项目主页：ZztIsolation/ZZZ-Scanner.Next
  • 发布页面：GitHub Releases

手动安装时可以选择：

  • ZZZ-Scanner.Next-win-x64-self-contained.zip：不要求电脑预先安装 .NET 8，体积较大，通常最省事；
  • ZZZ-Scanner.Next-win-x64-fdd.zip：电脑必须已经安装 x64 .NET 8 Windows Desktop Runtime。

必须完整解压压缩包。不要只复制 ZZZ-Scanner.Next.exe，它需要同目录中的 Data、Resources、OCR 模型、ONNX Runtime 和其他运行库。

3.3 从配装器自动查找、安装并启动 Scanner

当前程序按 B 版方式构建。点击“打开驱动盘扫描器”后，它会先查找配装器旁的 scanner 文件夹、已配置路径，以及附近名称以 ZZZ-Scanner.Next 开头的独立 Scanner 文件夹。

如果没有找到，程序会自动：

  1. 查询官方 GitHub 仓库的 Latest Release；
  2. 读取该版本的官方 scanner-manifest-*.json；
  3. 下载 Windows x64 self-contained ZIP；
  4. 校验 Release 资源大小、ZIP 的 SHA-256、解压路径和官方清单中的每个文件；
  5. 安装到配装器同目录的 scanner 文件夹；
  6. 校验成功后自动启动 Scanner。

下载和解压使用临时目录；失败时不会把半成品当成可运行 Scanner。首次自动安装需要能够访问 GitHub，并且配装器所在目录需要可写。下载与解压大小以官方最新版本为准。

正常操作步骤：

  1. 启动《绝区零》并使用简体中文界面。
  2. 打开背包中的驱动盘仓库。
  3. 在配装器“1. 录入驱动盘”区域点击“打开驱动盘扫描器”；首次使用时等待自动下载、校验和安装完成。
  4. 在 Scanner 中点击“检测窗口”。
  5. 检测成功后点击“开始扫描”。
  6. 扫描期间保持游戏可见，不要移动鼠标、滚动、切换标签、改变排序或遮挡窗口。
  7. 扫描完成后点击 Scanner 的“打开产物文件夹”。
  8. 回到配装器，点击顶部“导入 JSON（自动识别）”，选择本次扫描目录中的 export.json。

如果自动下载失败，可以从官方 Releases 手动下载并完整解压，再运行 ZZZ-Scanner.Next.exe；扫描完成后手动导入 export.json，不会影响配装功能。

3.4 Scanner 输出文件

手动版 Scanner 通常在其程序目录下生成：

Scans\YYYY-MM-DD-HH-mm-ss-fff-p<process>-<random>\

常见文件包括：

  • export.json：供配装器导入的驱动盘记录；
  • scan.log：版本、设置、进度、安全停止和错误信息；
  • ocr_diagnostics.csv：OCR 区域和耗时诊断；
  • *.error.txt：某个驱动盘识别失败的详情；
  • *.non15.txt：启用“仅 +15”时遇到的第一块低等级驱动盘。

导入配装器时优先选择完整扫描生成的 export.json。Scanner 的截图和日志可能包含可见游戏界面或本机路径，分享前请自行检查。

3.5 扫描建议

  • 第一次使用、改变分辨率或游戏更新后，先用 30 件左右做小规模测试。
  • 正常导入建议扫描 S 级 +15 驱动盘。
  • 扫描前确认套装排序和筛选状态符合预期。
  • 游戏和 Scanner 最好都以普通权限运行；如果游戏以管理员权限启动，普通 Scanner 可能无法控制它。
  • 识别数量或属性异常时先查看 scan.log，不要直接把可疑数据当作完整库存使用。

Scanner 的分辨率适配、窗口检测、OCR 和上游故障请以其官方仓库文档为准。本配装器负责查找已有 Scanner、在缺失时从官方 Latest Release 安装 self-contained 包、启动 Scanner，以及导入它生成的 JSON。

4. 导入、录入和库存管理

4.1 导入 JSON

顶部“导入 JSON（自动识别）”会根据文件结构自动处理：

  • Scanner 的 export.json / export.partial.json：作为驱动盘数据导入；
  • 通用驱动盘 JSON：作为驱动盘数据导入；
  • 本软件完整备份：恢复库存、角色保存方案及本地归属信息。

因此，WebUI 的普通 Scanner 导入仍然是导入驱动盘数据，不会把 Scanner 文件误当成角色要求配置。

Scanner 或通用格式导入会与当前库存合并。导入后请查看页面顶部的驱动盘总数，并抽查若干主属性和副词条。

4.2 截图 OCR

  1. 上传一张驱动盘详情截图，或点击粘贴区域后按 Ctrl+V。
  2. 识别结果会先填入录入表单。
  3. 红框表示存疑字段，必须人工确认。
  4. 修正套装、槽位、主属性和四条副词条。
  5. 点击“保存识别结果”。

截图 OCR 适合补录少量驱动盘，不建议替代完整库存扫描。

4.3 手工录入

选择套装和槽位后填写主、副属性。当前录入流程默认按 S 级 +15 驱动盘处理：

  • 主属性会按槽位限制，并校验 S 级 +15 的固定数值；
  • 百分比直接填写数字，例如 7.2% 填 7.2；
  • 每块盘最多填写四条副词条。

4.4 库存查看

库存区支持：

  • 按套装、槽位、属性和已存角色方案筛选；
  • 按文字搜索套装或属性；
  • 在卡片视图和表格视图之间切换；
  • 查看详情、编辑或删除单块驱动盘；
  • 查看驱动盘当前在本软件中的角色方案归属。

库存卡上的角色头像和归属表示本软件保存方案中的本地占用，不等同于游戏内实际装备状态。

5. 单角色配装

5.1 选择角色与音擎

  1. 选择代理人职业。
  2. 选择代理人。
  3. 选择实际核心技等级或面板状态。
  4. 确认自动匹配的音擎，也可以手动换成其他音擎或不计入音擎。
  5. 选择音擎精炼等级。

角色 60 级底数、所选核心技节点、音擎基础攻击和高级属性会按页面说明计入。技能触发类效果通常只显示为实战参考。

5.2 选择 4+2 套装

  • 4 件套套装只能选择一个。
  • 2 件套候选可以选择一个或多个，例如同时选择“自由蓝调”和“混沌爵士”。
  • 直接点击 2 件套列表即可逐个加入，不需要按 Ctrl 或 Shift。
  • 已选套装会显示在列表上方，点击标签中的 × 即可取消。

计算时程序会分别搜索每个“指定 4 件套 × 4 + 某个候选 2 件套 × 2”的分支，然后合并、统一排序，最终返回前 20 套。

4 件套本身不能同时作为该角色的 2 件套候选。

5.3 限制 4、5、6 号位主属性

可以分别指定 4、5、6 号位主属性，也可以选择“不限制”。不限制时，程序会从该槽位所有可用主属性盘中搜索。

限制越多，搜索越快，但也越可能错过其他可行方案。

5.4 面板目标与属性优先级

可填写的目标包括：

  • 暴击率；
  • 暴击伤害；
  • 最终攻击力；
  • 最终生命值；
  • 最终防御力；
  • 异常精通。

目标值为 0 时表示没有启用该目标。每个启用目标可以设置 1～6 的优先级，1 最高、6 最低。

如果没有任何方案能同时满足全部要求，程序会优先缩小高优先级目标的缺口，再比较下一优先级。例如攻击力为优先级 1、异常精通为优先级 2 时，程序先尽量贴近攻击目标，再在攻击表现相近的方案中选择精通更高的方案。

多个目标可以使用同一最高优先级。此时它们属于同一比较层级，程序会综合比较这一组目标的满足情况，而不是仅固定照页面从左到右选一个；只有这一层比较仍相同时，才进入下一优先级。

填写多个目标时，页面通常会自动选择更适合阈值约束的严格指标策略。仍可根据角色需求手动切换配装策略。

5.5 占用策略

  • 使用所有的驱动盘：允许当前角色搜索库存中的全部盘。
  • 避免使用已被占用的驱动盘：排除优先归属于其他角色方案的盘；归属于当前角色自己的盘仍可使用。

设置完成后点击“开始配装”。计算过久时可以点击“强制终止”。

6. 阅读配装结果

单角色计算最多返回前 20 套。每张结果卡会显示：

  • 排名；
  • 面板暴击率和暴击伤害；
  • 总攻击等主要面板；
  • 有效词条和期望指数；
  • 实际组成的 4 件套与 2 件套；
  • 六个槽位的套装、主属性和副词条；
  • 可展开的完整属性与排序说明。

“总攻击”等结果应以程序最终面板计算为准，不要只把盘面攻击力数值简单相加。基础攻击、攻击力百分比、固定攻击、音擎和套装静态加成都可能处于不同计算区间。

点击“存入角色”可把该结果的六块盘保存为当前角色的一套本地方案。若盘已归属于其他角色，程序会提示冲突，不会静默覆盖。

“导出结果 JSON”只导出最近一次计算结果，便于自行检查或留档。

7. 多角色配装

多角色模式用于一次给多个角色分配互不冲突的驱动盘。

7.1 添加角色目标

对每个角色重复以下步骤：

  1. 选择角色、核心技和音擎。
  2. 选择该角色的 4 件套及一个或多个 2 件套候选。
  3. 设置 4、5、6 号位主属性限制。
  4. 设置面板目标及各属性优先级。
  5. 填写“角色配装优先级”。数字越小越先分配，例如蕾米埃尔填 1、雅填 2。
  6. 点击“保存 / 更新当前角色目标”。

已经保存的角色会出现在“多角色配装目标与分配结果”区域。每个角色卡片可以折叠、展开、载入编辑或删除。

7.2 分配规则

点击“开始多角色配装”后：

  1. 角色按角色优先级从小到大依次计算；
  2. 同一角色内部仍按其属性目标优先级排序方案；
  3. 每个角色排名第 1 的方案成为实际分配方案；
  4. 该方案的 6 块盘立即为后续角色锁定；
  5. 低优先级角色不会使用已经分配给高优先级角色的盘；
  6. 同角色优先级时，按页面角色列表中的顺序处理；
  7. 某个角色没有找到方案时不会锁盘，后续角色继续使用剩余库存。

角色优先级解决的是“谁先挑盘”，属性优先级解决的是“这个角色内部先满足哪项面板要求”，两者不要混淆。

8. 数据保存与备份

8.1 库存文件

默认库存文件与 EXE 放在同一目录：

程序目录\state.json

它保存：

  • 驱动盘库存；
  • 已存角色配装方案；
  • 本地驱动盘归属及兼容数据。

页面顶部会显示当前实际数据文件。点击“修改路径”可将库存迁移到其他目录，例如 D 盘；点击“恢复默认”可恢复默认路径。

自定义路径记录保存在 EXE 同目录的 storage-config.json。因此移动整个程序文件夹即可一起移动默认库存、角色要求和路径配置。

首次运行本版时，如果程序目录中还没有 state.json，程序会尝试从旧 %APPDATA%\ZZZDriveBuilder 复制现有库存和角色要求。为避免误删数据，旧文件不会自动删除；确认新版读取正常后，可自行清理旧目录。

8.2 角色要求配置文件

多角色目标不再全部塞进 state.json，而是单独保存为与库存文件同目录、同前缀的文件：

state-character-targets.json

例如库存路径是：

D:\ZZZData\my-inventory.json

角色要求路径就是：

D:\ZZZData\my-inventory-character-targets.json

页面的多角色区域会显示实际角色要求配置文件路径。

8.3 推荐备份方法

日常建议同时保留：

  1. 顶部“导出完整备份”生成的文件；
  2. 当前库存 state.json 或自定义库存 JSON；
  3. 对应的 *-character-targets.json。

“导出通用驱动盘 JSON”主要用于驱动盘互通，不等同于本软件完整备份，通常不包含本地角色方案和全部归属信息。

9. 常见问题

导入 Scanner 文件后角色要求会被覆盖吗？

不会。Scanner 的 export.json 被识别为驱动盘数据；多角色要求保存在独立的 *-character-targets.json。

为什么 Scanner 按钮找不到程序？

新版会先自动查找，找不到时从官方 GitHub Latest Release 下载并安装。若仍失败，请确认网络可以访问 GitHub、配装器目录可写、磁盘空间充足，且安全软件没有拦截 ZIP 或 EXE。也可以手动启动 Scanner，再导入其 Scans 目录中的 export.json。

为什么扫描器检测不到游戏？

确认游戏已经启动、使用简体中文、打开驱动盘仓库，且本地/云游戏进程选择正确。游戏若以管理员权限运行，Scanner 也可能需要相同权限；更推荐两者都以普通权限运行。

为什么扫描到一半停止？

启用“仅 +15”时，遇到第一块低等级盘可能是正常停止。也可能是窗口被遮挡、用户输入、布局变化或 OCR 稳定性检查触发。查看本次目录中的 scan.log 和 *.non15.txt / *.error.txt。

为什么选了多个 2 件套却只有一个出现在某套结果中？

多个选择表示“候选分支”，不是同时装备多个 2 件套。标准 4+2 方案最终只会使用其中一个候选作为 2 件套，程序会搜索所有候选后统一排名。

为什么攻击力没有正好等于目标？

库存组合是离散的，未必存在精确值。程序会根据目标优先级选择缺口更小的方案，并在同层级中继续比较其他属性。若不希望超过目标，应使用相应严格策略并检查结果说明中的目标差值。

多角色优先级相同会怎样？

按页面中角色目标的列表顺序依次分配。排在前面的角色先锁定六块盘。

删除程序会丢库存吗？

11. 最短使用流程

如果已经有 Scanner 的 export.json：

  1. 启动 ZZZ_Multi_Agent_Drive_Optimizer_v2.0.0.exe；
  2. 点击“导入 JSON（自动识别）”并选择 export.json；
  3. 在库存区确认数量和若干属性；
  4. 选择角色、核心技和音擎；
  5. 选择一个 4 件套和一个或多个 2 件套候选；
  6. 设置 4/5/6 号位限制、面板目标和属性优先级；
  7. 单角色直接点击“开始配装”，多角色则逐个保存角色目标后点击“开始多角色配装”；
  8. 检查前 20 套结果，并保存需要的角色方案；
  9. 最后导出完整备份。
